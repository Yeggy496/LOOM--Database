# 后端对接与协作

## 分工建议

两位数据库成员可以分别维护“数据采集/人工标准”和“数据库工具/标注版本/集成交付”，合并时交换有版本的数据契约。使用 PR 讨论字段和数据，不互相覆盖发布的 SQLite 二进制文件。每次修改提交原始 JSON 或复核批次、迁移（如有）、更新的导出和验收记录。

队友仓库的公开作者与本库 `source.author` 都是归属信息，不是 App 登录用户。两个仓库中的 `pub-001` 也不是同一条记录；合并时必须增加数据集命名空间，例如 `teammate:pub-001`，并对原文哈希及来源进行核对。本库 ID 导入格式不接受冒号，可采用 `teammate-pub-001` 作为映射后的 ID。

## JSON 契约 v1

`exports/notes.json` 顶层含 `contract_version`、`scope`、`dataset_sha256`、`records`。每条记录包含原文与来源字段，并携带当前标注和版本。示例字段用途：

| 字段 | 后端如何使用 |
| --- | --- |
| `id` + 数据集命名空间 | 外部样本 ID，不用作真实用户笔记主键 |
| `origin` | 区分公开参考和模拟内容；默认业务评测可排除模拟内容 |
| `body`、`body_sha256` | 模型输入与一致性校验；不能被模型摘要覆盖 |
| `url`、`author`、`locator`、`source_checks` | 来源与核查轨迹 |
| `annotation_id`、`revision` | 当前标注版本，提交修订时要求期望版本 |
| `summary_zh`、`category`、`tags` | 候选整理，不是人工金标准 |
| `annotation_origin`、`review_status`、`reviewer` | 区分 AI 辅助整理、人工编写与人工确认 |
| `split`、`group_key` | 固定评测分组；不要把同组重新随机拆分 |
| `training_allowed` | 首版固定为 0，不作训练授权推断 |

`notes.json` 是导出的阅读契约，不是 `loomdb import` 的输入格式。导入格式见 `data/public_references.json` 与 `data/synthetic_inbox.json`。浏览页导出的筛选结果注明原始数据集指纹，不冒充完整数据集的新指纹。

## 与队友数据交换

| 队友字段 | 本库概念 | 必须注意 |
| --- | --- | --- |
| `original_excerpt` / `original_sha256` | `body` / `body_sha256` | 保留原文，重算哈希后对照 |
| `url` / `author` / `excerpt_locator` | `source.url` / `source.author` / `locator` | 不丢来源，不映射成内部用户 |
| `summary_zh` / `annotation` | 新的 `annotation_revisions` | 交换时保留状态及来源；不要让导入器假称已完成人工复核 |
| `category=note` | `knowledge` 候选 | 人工确认分类含义后再映射；本库另外区分 task |
| `license_status=open` | `documented` 候选 | 必须保留具体许可名称/链接；不等于训练许可 |
| `source_check` | `source_checks` | 来源核查不替代标注复核 |

本仓库没有自动下载或导入队友数据。需要合并时增加独立转换脚本、版本化映射及回归测试，不把相同 ID 当作相同样本。

## MySQL 开发库

用新建的独立空库测试，不能导入已有生产库。以下以 MySQL 客户端为例（交互式输入密码）：

```text
mysql -u your_user -p
CREATE DATABASE loom_corpus_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;
USE loom_corpus_dev;
SOURCE schema/mysql/V001__corpus.sql;
SOURCE exports/mysql_seed.sql;
```

不要使用 `--force` 忽略 SQL 错误。种子使用普通 INSERT，不覆盖旧数据；8 表在事务中导入。基线 DDL 在 MySQL 中不能按普通 DML 事务保证整体回滚，失败时检查并重建专用测试库后再试。

MySQL CI 使用临时 MySQL 8.0 / 8.4 服务，并对照 SQLite 检查每表每字段，另验不可变历史触发器。SQLite FTS 索引和迁移记录不移植到 MySQL；应用搜索服务需要独立设计，不能直接把 SQLite MATCH 语法搬过去。

## Spring Boot 接入边界

可先把样本 JSON 导入测试环境，再通过应用的 Controller/Service 读数据。真正的用户域应另建账户、笔记、附件、AI 任务和加工结果，使用用户 ID 做所有访问的权限约束。任务重试、密钥、Redis、语音/OCR、离线版本冲突属于后端能力，本仓库没有实现它们。

建议应用 API 采用类似以下约定（**设计建议，当前没有这些 HTTP 服务**）：

```text
GET  /api/research-samples?origin=public_excerpt&split=dev
GET  /api/research-samples/{dataset}/{sampleId}
POST /api/research-samples/{dataset}/{sampleId}/annotations
     { expectedRevision, summaryZh, category, tags, reason }
```

过期版本返回 409；操作者由登录身份决定，不能信任客户端提交的 `reviewer`。真实 App 用户笔记另走自己的受保护接口，不把此公开样本浏览页部署成用户资料后台。
